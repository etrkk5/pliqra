# Pliqra 2.1.0-rc.3

Connect models, stream through native clients, and govern independent installations from one console.

**Release candidate:** intended for evaluation and deployment acceptance. Synthetic tests do not establish customer adoption, production capacity or geographic disaster-recovery guarantees.

## What's new

- **Live native streaming:** incremental text and function arguments across Responses, Anthropic Messages and the common Chat boundary. Bounded parsing, explicit terminal/error handling and disconnect accounting. Full-output guardrails and forced tool validation retain checked, buffered delivery.
- **Fleet management:** explicitly pair independent workspaces, filter combined usage, map portable gateway policies, review immutable before/after plans with a different administrator, apply with conditional writes and durable receipts, detect drift and prepare reviewed rollback. Available in the console and API.
- **Installable SDKs:** small Python and JavaScript/TypeScript distributions, clean-install checks, checksummed release assets and an identity-based package publication workflow. SDK version 0.1.0-rc.1 is independent of gateway 2.1.
- **Repeatable synthetic acceptance:** separate installed applications, official native API clients, verified TLS, two active gateway sites, an independent branch/controller, load/soak measurements and model/database interruption exercises. The independent reference server and core conformance profile remain available without gateway imports.
- **Apache-2.0 distribution:** the image and SDK packages include LICENSE and NOTICE. Linux AMD64/ARM64 images carry SBOM and build provenance.

## Install

```sh
mkdir pliqra && cd pliqra
curl -fL -o compose.release.yaml https://github.com/eturkok/pliqra/releases/download/v2.1.0-rc.3/compose.release.yaml
docker compose -f compose.release.yaml pull
docker compose -f compose.release.yaml up -d
```

Open **http://localhost:8088**, create an administrator and connect a model endpoint reachable from inside the container. Data persists in `pliqra-data`. Test the candidate in a separate workspace first.

## Upgrade and boundaries

Schema **6**, inference contract revision **5**, wire protocol draft **0.1**. Back up data and encryption keys, stop old replicas, upgrade all sites together, then renew application bindings. Older images require their matching pre-upgrade backup.

Multi-DC active gateways still share one writable PostgreSQL authority and stop admitting calls when it is unavailable. Fleet connects independent authorities; its rolling snapshots do not create one cross-installation quota. Rollouts are atomic per member and may finish partially. Two-person review is a controller workflow, not an independent cryptographic assertion on the member. Native APIs remain documented subsets; guarded output is buffered. WAN partitions, PostgreSQL primary promotion, real model quality, customer IdPs/NeMo/Vault and external protocol adoption require environment-specific acceptance.
