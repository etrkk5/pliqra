# Pliqra 2.1.0-rc.1

The first published Pliqra 2.1 release candidate brings endpoint-first AI services, custom gateway policies and explicit model contracts to a ready-to-run container distribution.

**Prerelease:** intended for evaluation and deployment acceptance. Production capacity, geographic failover and all vendor integrations are not certified by this release.

## Highlights

- **Active/active multi-DC:** one shared writable PostgreSQL authority for strict global request/token quotas, budgets and concurrency; local-first model routing and allowed site/region placement.
- **Site operations:** independent health/circuits per observing site, audited active/draining/standby controls, readiness/liveness and supervised recovery of fenced gateways without replaying started inference.
- **Governed AI services:** model capability contracts, explicit application bindings, custom gateways, composable guardrails and detailed team/project/user/site usage and routing records.
- **A complete workspace:** console/API configuration, federated identity, isolated organizations, prompts, batches, external judges and evidence-gated canaries. Python, JavaScript/TypeScript and Go clients accompany the draft protocol.
- **Ready-to-run images:** Linux AMD64 and ARM64, exact image digest, SBOM/build provenance and downloadable Compose configuration. No source checkout or registry login is needed.

## Install

```sh
mkdir pliqra && cd pliqra
curl -fL -o compose.release.yaml https://github.com/etrkk5/pliqra/releases/download/v2.1.0-rc.1/compose.release.yaml
docker compose -f compose.release.yaml pull
docker compose -f compose.release.yaml up -d
```

Open **http://localhost:8088**, create an administrator and connect a running model endpoint. Workspace data persists in `pliqra-data`; stop the old deployment before reusing an existing workspace.

## Upgrade and acceptance

Schema **5**, inference contract revision **4**, wire protocol draft **0.1**. Back up data and the encryption key; stop old replicas, upgrade all sites together and renew application bindings. Returning to an older schema requires restoring its matching backup.

The release pipeline reruns the functional suites and checks the published image on native AMD64/ARM64 runners. The 2.1 functional validation includes real shared-PostgreSQL tests and a same-host, two-site container exercise. Actual geographic/WAN faults, PostgreSQL primary promotion, production load and customer NeMo/Vault/IdP/model acceptance remain deployment work. Native API compatibility is a documented subset; native Responses/Messages streaming is buffered. Disconnected sites stop admitting calls to preserve shared-authority consistency.
